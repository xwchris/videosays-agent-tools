## Channels

### WorkBuddy / SkillHub

Checked on 2026-09-18: SkillHub's `videosays` result is the **old** `@clawhub_xwchris/videosays` mirror, sourced from `https://clawhub.ai/xwchris/videosays`, version `1.0.0`. Its `summary_zh` contains the same English text as `summary`. This matches the English card shown in WorkBuddy. The adjacent `douyin-to-text` and `dy-caption` entries are also attributed to `xwchris` by SkillHub.

Updating `@wegofuture/videosays` or GitHub alone does not prove this old mirror has updated. Inspect the exact displayed entry and its upstream owner before publishing. Prefer claiming/updating or consolidating the existing entry over adding more near-duplicate skills. Claiming an entry requires the publisher's SkillHub account; do not treat the local package build as a marketplace update.

Repository arrangement:

- Keep the stable machine identifier `videosays` and one shared execution workflow.
- Portable `SKILL.md`: one English description and one English instruction body. English is this repository's maintenance choice, not a requirement of the Agent Skills standard. Agents respond in the user's language; API origin does not depend on that language.
- WorkBuddy: Chinese `display_name`, `description`, and `description_zh`; English `display_name_en` and `description_en`. The locale fields are WorkBuddy-specific top-level fields, not part of the portable Agent Skills frontmatter. The generated package reuses the canonical instruction body verbatim.
- Chinese display name: **抖音文案提取 · Videosays**. English display name: **Videosays · Video to Text**.
- For a registry with only one title/summary, select that channel's language instead of concatenating translations. The canonical ClawHub listing and GitHub/skills.sh distribution use English. A Chinese channel should use the Chinese listing copy and the same execution instructions. Do not create another discoverable skill ID merely to change language, or assume a registry automatically translates the body.

The portable Agent Skills format specifies `name` and `description`, but no standard locale-switching fields. Channel-specific display metadata stays outside the canonical file. This keeps ordinary installers compatible without maintaining two workflows.

Build a WorkBuddy upload ZIP (Node.js and `zip` required):

```bash
npm run build:skill:workbuddy
```

Output: `dist/workbuddy/videosays-workbuddy-<CLI-version>.zip`, with a root `SKILL.md`. The version is taken from `packages/cli/package.json`; build again after the CLI release version changes. This prepares files locally and does not upload or publish them.

Read-only checks for the existing mirror:

```bash
curl 'https://api.skillhub.cn/api/v1/skills/videosays'
curl 'https://api.skillhub.cn/api/skills?keyword=videosays&pageSize=5'
```

## Update Checklist

1. Update `skills/videosays/SKILL.md`. Keep executable examples pinned to the tested npm CLI version; publish that CLI version before submitting the Skill to registries.
2. Sync `SKILL.md` and the website `packages/web/public/SKILL.md`.
3. Run `scripts/check-skill-sync.sh`.
4. Publish npm CLI if CLI behavior changed.
5. Publish ClawHub update.
6. Rebuild and upload Agensi zip if the skill content changed.
7. Recheck search on ClawHub, SkillUse, skills.sh, SkillsLLM, AgenticSkills, and Agensi.
8. Rebuild the WorkBuddy ZIP and update the correct existing marketplace entry. Verify Chinese/English listing fields and the actual published version, including SkillHub's upstream source.
